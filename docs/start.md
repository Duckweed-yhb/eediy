# 入门实践：从 C 语言到 MCU 小系统

> 八个板块是地图，不是八门必修课。这一页只做一件事：把其中四个阶段串成一条线——**C 语言 → 电路与数字逻辑 → MCU 外设 → 一个可验收的小项目**。每个阶段都写清四件事：适合谁、必学什么、动手做什么、怎么算过关。
>
> 这条路线以嵌入式入门为目标，不代表所有 EE 方向的学习顺序。想知道它在整个体系里的位置、共同基础有多大、另外四个方向怎么分，看 [课程体系](/curriculum)；想知道自己该不该从这段开始，看 [如何使用本站](/guide)。
>
> 学时是按每周投入 10–15 小时估算的，不是任何课程的官方数据。强度不同，自己按比例伸缩。

## 为什么是这四段

这条路线的每一段都有明确的产物，而且产物能交给别人看：一段能在自己机器上编译运行的 C 程序、一个用仿真和面包板都能复现的电路、一个能烧进板子的外设工程、一个连续跑 48 小时的设备。

后面还有 [04 电机与运动控制](/04-motor-control/README)、[05 电力系统](/05-power-system/README)、[06 信号与通信](/06-signal-communication/README)、[07 数字逻辑与 FPGA](/07-digital-fpga/README) 四个板块。它们不是这条线的前置，而是这条线走完之后按方向分叉的延长线。**先能独立做完一个小系统，再去挑方向**，可以为后续选课提供具体的问题背景。

| 阶段 | 主线内容 | 这一段的产物 | 估计投入 |
|---|---|---|---|
| 一 · C 语言 | 数据类型、控制流、数组、指针、结构体、文件与字符串 | 一个自己写的、能处理错误输入的命令行小程序 | 60–100 小时 |
| 二 · 电路与数字逻辑 | 电路基本定律、一阶瞬态、组合与时序逻辑 | LTspice 仿真 + 面包板实测两份记录 | 60–100 小时 |
| 三 · MCU 外设 | GPIO、中断、定时器、串口、I2C / SPI、ADC | 从空工程长出来的外设驱动，每个都有观测手段 | 80–120 小时 |
| 四 · 小项目 | 把前三个阶段拼成一个完整设备 | 一个能被别人验收的作品 | 40–80 小时 |

## 阶段一 · C 语言

**适合谁**：完全没有编程经验，或者只写过 Python / MATLAB 脚本的人。这是整条线的起点，没有前置。

**必学**：变量与类型、`if` / `for` / `while`、函数与参数传递、数组、指针、结构体、字符串与 `strlen` / `strcpy`、`printf` / `scanf` 的格式符。

**可选拓展**：文件读写、`malloc` / `free`、多文件编译与头文件、`make` 或 CMake。做 MCU 之前不必碰链表和树。

**推荐资源**：

- [Harvard CS50x](https://cs50.harvard.edu/x/)：英文，免费，课程官网。选它的理由是第 1–5 周直接用 C 讲指针和内存，围绕程序设计与内存使用安排练习；而且作业有自动评测，写完就知道对不对。
- [C 语言学习笔记](/01-math-programming/c-language)：本站笔记，8 章语法骨架加每章可运行代码。适合当速查表，不适合当唯一教材。
- 《C Primer Plus》（Stephen Prata，第 6 版）：书。适合当参考书，不必从头读到尾。

**动手任务**：写一个命令行程序，从标准输入读一行形如 `led on 500` 的命令，解析出「设备名 / 动作 / 参数」三段，打印解析结果；遇到 `led on abc` 这种非法参数要报错并且不退出。全程不用任何第三方库。

**过关标准**：能不看笔记，从空文件写出来并编译通过；输入 `led on` （少一段）、`led on abc`（参数不是数字）、空行三种情况都不崩溃，报错信息能指出错在哪。**注意区分**：跟着教程敲完一遍不算过关，这里要的是关掉教程、只留题目描述，还能自己写出来。

**下一步**：进入电路与数字逻辑。C 里学的位运算和数组，会在寄存器配置和缓冲区里天天用到。

## 阶段二 · 电路与数字逻辑

**适合谁**：学过高中物理的电路部分，或者正在上大一电路课。这一阶段的电路分析和图形化仿真不以 C 语言为前置；若要编程处理测量数据，再补充所需的程序设计知识。

**必学**：欧姆定律与基尔霍夫定律、戴维南等效、电容充放电与时间常数、RC 一阶电路；数字部分：布尔代数、组合逻辑（真值表 → 卡诺图 → 电路）、触发器、同步时序电路。

**可选拓展**：运放的虚短虚断与基本放大电路、三极管开关与放大、模电的频响与反馈。这些等阶段四有具体需求时再回头补，比先学完再用记得住。

**推荐资源**：

- [02 电路与电子学](/02-circuit-electronics/README)：本站板块页，列了电路原理、模电、数电三门主线课和对应教材，选一门中文课跟完即可。
- [LTspice](https://www.analog.com/en/resources/design-tools-and-calculators/ltspice-simulator.html)：官方免费仿真器。选它的理由是它够轻、上手快，画完电路当场能看波形，不用先学一套工程流程。
- [07 数字逻辑与 FPGA](/07-digital-fpga/README) 的数字逻辑部分：只读理论课与状态机，不必碰 Verilog。Verilog 留到确实需要并行逻辑时再学。

**动手任务**：搭一个 RC 充电电路，先用 LTspice 仿真，得到时间常数和到达 63.2% 电压的时间；再用面包板、电阻、电容和示波器测量同一个电路；没有示波器时，可选择秒级时间常数，用万用表配合计时记录多个电压点，注意仪表刷新速度与输入阻抗的影响，把两组数字写在一起对比。

**过关标准**：能手算 `τ = RC` 并解释为什么是 63.2%；实测与仿真的偏差能说出原因（电容公差、万用表内阻、面包板接触电阻都行）；数字电路侧，能独立把「三人表决器」的真值表变成电路，并比较与非门实现和与门、或门组合实现的逻辑等价性。**不算过关**：只是在仿真里拖动滑块看到波形变了，却说不出波形为什么长这样。

**下一步**：进入 MCU。阅读开发板原理图时，可先识别电源、复位、时钟与所用接口；不熟悉的部分结合器件手册继续学习。

## 阶段三 · MCU 外设

**适合谁**：能写结构体、能看懂面包板电路。前置是阶段一和阶段二。

**必学**（按这个顺序，一个外设一个实验）：GPIO 输出与输入 → 外部中断 → 定时器（定时中断、PWM 输出、输入捕获）→ UART 收发 → I2C 或 SPI 读一个传感器 → ADC 采样。

**可选拓展**：DMA、看门狗、FreeRTOS。RTOS 等你有两个以上任务真的需要并行时再上，别一上来就套框架。

**推荐资源**：

- [03 嵌入式与单片机](/03-embedded-mcu/README)：本站板块页。浙大那门走寄存器 + 库函数，电子科大那门走 CubeMX + HAL，**选一门开始，另一门当对照**，不要同时跟两门。
- [STM32 参考手册](https://www.st.com/en/microcontrollers-microprocessors/stm32-32-bit-arm-cortex-mcus.html)：ST 官方页面，按你的具体型号找对应文档。选它的理由只有一个：外设寄存器的行为以它为准，教程和视频都可能过时。
- [08 硬件工具链](/08-hardware-toolchain/README)：示波器、逻辑分析仪、串口助手怎么用，遇到问题再查。

**动手任务**：**从空工程开始**，不下载任何现成例程工程。自己配置时钟树，让一个定时器每 1 ms 中断一次，在中断里翻转一个 GPIO 接的 LED；同时用 UART 每秒上报一次按键计数。要求中断里不做耗时操作，主循环负责串口输出。

**过关标准**：能用示波器或逻辑分析仪量出 1 ms 的中断周期和串口波特率；能解释清楚 HAL 的回调函数是在哪个上下文里被调用的；设计两个可控中断源，观察优先级配置对响应顺序的影响，并解释实验条件。**不算过关**：拿别人的工程改几个宏定义跑通了，却说不清时钟从哪来、中断向量表在哪。

**下一步**：进入阶段四，把外设拼成一个完整设备。

## 阶段四 · 一个可验收的小项目

**做什么**：环境监测节点。STM32 采集温湿度与光照，OLED 屏显示，按键切换页面，串口每秒输出一行 CSV。这是 [03 嵌入式与单片机](/03-embedded-mcu/README) 项目实战里的入门项，下面给出具体的实现与检查要求。

**必须有的东西**：一块开发板、一个温湿度传感器（如 AHT20 或 SHT30）及一个光照传感器（如 BH1750）、一块 SSD1306 OLED、一个按键。

**验收标准**（逐条都能当众演示）：

1. 上电后 3 秒内屏幕出现读数，且数值随环境变化，不是写死的常量。
2. 串口每秒输出一行 `时间,温度,湿度,光照`，格式固定，用脚本能解析。
3. 拔掉传感器后屏幕显示「传感器离线」，程序不卡死，重新插回能自动恢复。
4. 连续上电 48 小时不重启、不花屏、串口不中断。

**「跟教程做出来」和「独立做出来」的分界**：

| 现象 | 跟教程 | 独立 |
|---|---|---|
| 芯片地址 | 照抄教程的 `0x38` | 会查 datasheet 或扫描 I2C 总线确认 |
| 屏幕不亮 | 换一块屏试 | 先量上拉电阻和供电，再看地址和初始化序列 |
| 读数不对 | 加个系数凑 | 能说出是量程、分辨率还是单位换算的问题 |
| 程序跑飞 | 重新烧录 | 会看 HardFault 寄存器，知道卡在哪条指令 |

**下一步**：走到这里，再挑方向。五个方向的课程链、第一个项目与验收标准，见 [方向分流](/directions)；想把这条路走成一条完整的嵌入式线（S0 工具测量 → S6 项目验收），见 [嵌入式与硬件系统](/directions/embedded)。[04 电机与运动控制](/04-motor-control/README) 接的是 PWM 和闭环；[07 数字逻辑与 FPGA](/07-digital-fpga/README) 接的是并行时序；[05 电力系统](/05-power-system/README) 和 [06 信号与通信](/06-signal-communication/README) 更偏数学建模，可以在有项目牵引时再进。

## 常见的三种走偏

- **一直在看课，从不动手**。判断方法很简单：过去两周里，有没有产出过任何能运行、能测量、能给别人看的东西？没有就是走偏了。
- **同时开五门课**。一次只跟一门主线课，其他都算拓展，排在主线之后。
- **把收藏当成进度**。这个站的价值在路线和顺序，不在链接数量；书签夹里躺着二十门课不代表学过任何一门。
