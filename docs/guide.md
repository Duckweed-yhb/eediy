# 如何使用本站

> 本站按八个知识板块维护内容，学习顺序由先修关系与目标方向确定。本页说明读者分类、基础自检、课程选择及学习计划制定方法。

## 读者分类与建议路径

### A. 初学者与跨专业学习者

**适用基础**：尚未系统学习电路与程序设计，希望了解电气电子工程的基本方法。

**建议路径**：从 [入门实践路线](/start) 开始，完成命令行 C 程序及基础 LED 电路实验，建立程序行为、电路参数与测量结果之间的联系。

**准备条件**：具备 C 编译环境的计算机；进行实物实验时，按任务要求准备面包板、LED、电阻及适当的低压限流电源。器件与仪器清单以具体实验要求为准。

**范围控制**：优先完成入门任务；达到阶段验收要求后再进入进阶内容。

### B. 在校生，想补课程理解

**典型情况**：正在上电路、模电、信号与系统、电机学，课听懂了但做不出题，或者只会套公式。

**资源选择原则**：每门课程优先采用一套主教材或主课程，围绕当前知识缺口补充参考材料，避免重复学习与任务分散。

**做法**：每一门正在上的课，只配一门主课，以及一个能用 2 小时做完的仿真或小实验。主课链接在对应板块页的「核心公开课与课程」里。记录模型参数、仿真结果与误差分析，作为阶段学习成果。

**跳过什么**：跳过整个 L2 方向分流。你在学校有课，课外时间优先补「手上这门课」的缺口，不需要现在就定方向。

### C. 有基础，想进某个方向

**典型情况**：C 语言和电路都过关了，或者在读研、在工作，想在嵌入式 / 电机 / 电力 / 信号 / FPGA 里选一条做下去。

**学习重点**：依据目标能力确定课程链，并设置可检查的阶段成果。

直接去 [方向分流](/directions) 选一条，按那条线的顺序走。判断标准很简单：**这条线的最后一个项目，你能不能拿出东西给别人看**。

**跳过什么**：跳过 L0 入门体验。但要先花半天做 [共同基础](/foundation) 里的自检，确认基础没留下洞——尤其是「指针」和「基尔霍夫定律」这两处。

## 怎么判断已有基础

不看「学过什么课」，看**能不能做出来**。下面每一条都是 10 分钟内可验证的：

| 检查项 | 通过标准 | 不通过就去 |
|---|---|---|
| C 语言指针 | 写一个 `swap(int*, int*)` 并解释为什么传值不行 | [C 语言学习笔记](/01-math-programming/c-language) |
| C 语言结构体 | 定义一个含数组成员的结构体，用 `->` 访问并修改 | 同上，第 8 章 |
| 电路定律 | 给一个两电源的电阻网络，用节点法算出各支路电流 | [02 电路与电子学](/02-circuit-electronics/README) |
| 一阶瞬态 | 算出 RC 充电到 63.2% 的时间，并解释 τ 的物理意义 | 同上 |
| 数字逻辑 | 把三人表决器的真值表化简成电路 | [07 数字逻辑与 FPGA](/07-digital-fpga/README) |
| 测量操作 | 用万用表测一个电阻分压点的电压，误差 < 5% | [共同基础 · 测量](/foundation#测量与实验动手能力) |

六项里过四项即可进入 L1；过六项可直入 L2 的方向线。**过不了的项就是你唯一该补的洞**，其他都别管。

## 怎么选一门主课

一次只跟**一门**主线课。这是本站最硬的建议，因为违反它的代价最高。

**选课的四条依据**，按优先级排列（这也是课程页统一的字段）：

1. **内容覆盖**：这门课讲的范围，能不能覆盖你要走的路上的下一门课。例：学嵌入式之前，C 语言课必须讲到指针和结构体，只讲语法的不够。
2. **解释质量**：同一概念，它是给推导还是给结论。自学者缺助教，只能靠材料本身把话说清。
3. **作业与实验**：有没有可运行、可检查的任务。没有作业和实验的课，对自学者的通过率很低。
4. **可访问性与维护**：能不能免费看、开课是否规律、链接是否还在。这一条不决定课好不好，但决定你下周还能不能接着学。

**学校名气和播放量不作为唯一依据。** 一门播放量 200 万的课，如果实验环境需要实验室、自学者跑不起来，对你就是不适用的。

**选定了就不要再开第二门。** 想换课的判断点只有一个：同一门课卡了 3 周且没有进展。换的时候把旧的删掉，别留着「以后再看」。

## 理论、习题、仿真、实物怎么排

EE 和纯软件不一样：公式最后要落到一个能测量的量上。一次完整的循环是五步，不是读完一章：

```text
理论分析 → 仿真预测 → 实验或测量 → 解释差异 → 整理成可复现的记录
```

| 环节 | 做什么 | 是否可以跳过 |
|---|---|---|
| 理论分析 | 手算一个结果，写出预期值（比如 τ = RC = 1 ms） | 不能跳 |
| 仿真预测 | 在 LTspice / Python 里跑同一个电路或系统，记下波形与数值 | 可以推迟，但做完仿真再上实物，能少烧几块板 |
| 实验或测量 | 面包板 / 开发板 / 示波器上的真实结果 | **优先级最低的方向可以暂时用仿真代替**，但要写明是仿真 |
| 解释差异 | 实测与仿真差 20%，差在哪：电容公差、探头负载、接线电阻、采样率 | 不能跳，这一步才是学会 |
| 整理记录 | 一张表或一段文字：假设、参数、结果、差异原因 | 不能跳，否则下次重做 |

对数学类课程（微积分、线代、概率）不做硬件，做完「理论 + 习题」即可，不必强行加实验。

**关于实验条件的边界**：本站推荐的入门项目全部是**低压、限流**条件下的（5 V / 3.3 V，串限流电阻）。涉及市电、高压、大功率逆变的内容，只给仿真方案或明确要求在有监督条件的实验室完成，不在自学场景下推荐自己搭。

## 时间有限时先做什么

按这个顺序砍，砍到时间够为止：

1. **先砍「以后会用到的课」**。电磁场、数学物理方程这类课，等真的要用再补。
2. **再砍同方向的第二、第三门课程**。一门主课 + 一门对照课，够了。
3. **不要砍实验与验收**。做完一个小项目胜过看完三门课，因为它是唯一能被检验的东西。
4. **最后才砍理论**，且只砍「下一门课用不上的部分」。

每周 5 小时以下的极端情况：只做一件事——把当前阶段的**一个练习**做完并写下 3 行结论。不要开新课。

## 三个门槛怎么补

### 英文

EE 最好的材料大多是英文的（datasheet、应用笔记、OCW）。不需要先学英语再用材料，直接在材料里泡：

- 第一次读 datasheet，只找三个东西：绝对最大额定值、推荐工作条件、引脚定义。其余先跳过。
- 视频课开英文字幕，遇到听不清的按暂停看字幕，不回头重听。
- 一个术语读三遍还别扭，就去查中文译名并记在笔记里。术语表比语法书有用。

### 数学

不要「补完数学再学专业课」。数学按需补，触发条件很清楚：

| 卡在什么地方 | 补什么 |
|---|---|
| 电路瞬态题解不出 | 一阶线性微分方程 |
| 节点法算不明白 | 线性方程组、矩阵 |
| 信号与系统的卷积看不懂 | 积分与图形变换 |
| 控制理论的根轨迹看不懂 | 复变函数初步 |
| 电磁场、传输线 | 矢量微积分、偏微分方程 |

每项补到「能跟着教材算题」就停，不要追求体系完整。

### 硬件门槛（没钱、没设备、没实验室）

按成本从低到高：

1. **零成本**：LTspice（免费）、Python + NumPy、Logisim 之类的逻辑仿真、Arduino 官方在线例程阅读。
2. **50–100 元**：面包板、杜邦线、电阻电容包、LED、万用表。足以做完分压、RC、限流、运放基本电路。
3. **100–300 元**：一块 STM32 最小系统板或 Nucleo 板 + USB 转串口。足以做 GPIO、串口、定时器、I2C 传感器。
4. **需要仪器的**：示波器、逻辑分析仪。先借实验室的，或买百元级 USB 逻辑分析仪；实在没有，用「串口打印 + 单片机定时器计数」做替代验证，并注明这是间接测量。

**用替代方案时必须写清楚限制**：串口打印没有波形，抓不到毛刺；仿真没有器件公差，量不到真实噪声。写在记录里，比假装测过要诚实。

## 学习安排示例

下面两套都只是**示例**，不是标准答案。假设和投入写清楚了，自己按比例缩放。

### 示例一：在校生，每周 10 小时

**假设**：大一或大二，正在上电路课，C 语言刚学完，没有开发板。

| 时间 | 做什么 |
|---|---|
| 周一到周五，每天 1 小时 | 跟学校电路课同步：当天讲的例题自己重算一遍，卡住的去板块页找对照课的一节 |
| 周六 2 小时 | LTspice 把本周电路仿真一遍，记录与手算的差异 |
| 周日 3 小时 | C 语言练习：本周一个程序题，自己写、自己调试、不留 bug |

**三周后应有的产出**：3 张仿真截图 + 3 段差异说明 + 3 个能跑的小程序。

### 示例二：已工作 / 研究生，每周 6 小时

**假设**：C 语言过关，电路忘得差不多，想进嵌入式方向。

| 阶段 | 内容 | 验收 |
|---|---|---|
| 第 1–2 周 | 补电路：欧姆定律、分压、RC、二极管限流 | 在面包板上做出分压电路，实测误差 < 5% |
| 第 3–4 周 | 补测量与工具：万用表、电源限流、串口助手 | 能独立判断「LED 不亮」是接反、限流过大还是引脚配错 |
| 第 5–10 周 | MCU 外设：GPIO → 中断 → 定时器/PWM → 串口 | 每个外设一个小实验，附一张波形或串口截图 |
| 第 11–14 周 | 传感器与显示：I2C 读一个传感器 + OLED | 屏幕上的数值随环境变化 |
| 第 15–20 周 | 小项目：环境监测节点 | 验收标准见 [嵌入式方向路线](/directions/embedded) |

**六小时怎么分配**：3 小时看课与动手，2 小时排错（一定会花这么多），1 小时写记录。

## 这一页的边界

- 以上学时都是**编辑估计**，基于「每周 10–15 小时、有高中数学和一点编程基础」的假设。没有任何机构背书，也不等于某门课的官方学时。
- 不承诺「几个月精通 EE」。这条路线的目标是：在选定方向上，能独立做完一个可验收的小系统，并能解释它为什么这样工作。
- 不承诺与正式学位等效。学分、培养方案、毕业要求以你所在学校的教务文件为准；同校信息见 [哈工大（深圳）电气指南](/campus/hitsz-ee/)。
