# 嵌入式与硬件系统：一条能走完的路线

> L2 五条线里的第一条，也是目前唯一写到可执行程度的一条。从「会写 C」走到「一块能连续跑 48 小时的小系统」。
>
> 选这条路线的依据：本站 03 板块的课程卡片最完整（Arduino 官方、浙大 STM32、电科大 HAL、FreeRTOS 官方、ARM Cortex-M 文档），08 板块有 18 条工具条目，01 板块有 C 语言笔记与 [CS50x 课程页](/courses/cs50-c)。基础、课程、工具三块齐了，缺的只是串起来的顺序与验收。

## 适合谁

- 想做一个能被别人看见的硬件作品，但不知道先学哪门。
- 已经会一点 C，但没碰过 MCU 外设。
- 电子类专业在读，课上过但实验都靠抄。

**前置**：能写 100 行以上的 C 程序并自己调通；能用万用表测电压；知道欧姆定律。不满足就去 [共同基础](/foundation) 的自检表，按缺的项补，别硬上。

**不需要**：微积分的深水区、模电的放大器设计、FPGA。做这条路线的入门项目，一支烙铁都不是必需的。

## 六个阶段

时长是**编辑估计**，按每周 8–10 小时计。没有任何官方依据。

| 阶段 | 做什么 | 出口 | 估计 |
|---|---|---|---|
| S0 工具与测量 | 万用表、电源限流、面包板、串口助手 | 能独立判断 LED 不亮的原因 | 1–2 周 |
| S1 C 语言收口 | 指针、结构体、位操作 | 不看教程写出 100 行程序 | 2–4 周 |
| S2 电路与数字逻辑 | 分压、RC、二极管、逻辑门、状态机 | 手算与实测差 < 10% | 3–5 周 |
| S3 MCU 外设 | GPIO、中断、定时器/PWM、UART | 每个外设一张波形或截图 | 4–6 周 |
| S4 总线与传感器 | I2C、SPI、ADC、OLED | 屏幕读数随环境变化 | 3–4 周 |
| S5 工程化 | Git、分层、调试、RTOS 入门 | 代码能给别人接手 | 2–4 周 |
| S6 综合项目 | 环境监测节点 | 四条验收标准全过 | 3–5 周 |

### S0 工具与测量

**目标**：让「接错了」这件事变得可诊断。

**学什么**：数字万用表测电压/电阻/通断；可调电源先设限流再上电；面包板内部连通规则；USB 转串口与串口助手。

**依赖**：无。这是整条线的第 0 步，跳过它的人后面一定卡在「不亮」。

**练习**：

1. 用 5 V 电源、两个 1 kΩ 电阻做分压，万用表测得 2.5 V（±5%）
2. 一个 LED 串 330 Ω 接 3.3 V，算出电流约 5 mA，实测亮度与电阻的关系
3. 把电源限流设到 50 mA，故意把 LED 极性接反，观察电源进入限流而不是烧毁

**验收**：

- 能说出「LED 不亮」的三种可能原因并按顺序排查（极性、限流、供电）
- 分压实测与理论差 < 5%
- 知道为什么先设限流再上电

**下一步**：S1。

### S1 C 语言收口

**目标**：从「看懂」到「写得出」。

**学什么**：指针与地址、结构体与 `->`、数组与缓冲区、位运算（置位/清位/读位）、`volatile` 为什么在中断里要用。**不学**：文件格式化读写、复杂指针声明、链表（除非你要做解析器）。

**主推荐**：[01 板块的 C 语言笔记](/01-math-programming/c-language) + [Harvard CS50x 的 C 部分](/courses/cs50-c)。CS50x 课程页里写了这门课的先修、投入、完成标准与局限。

**练习**：

1. 写 `swap(int*, int*)`，并解释为什么传值不行
2. 定义含 `char name[16]` 的结构体数组，按分数排序（结构体内用字符数组，不能用 `=` 赋值）
3. 写一个环形缓冲区：`push` / `pop` / `is_full`，用两个下标而不是搬移数据
4. 用位运算把某个字节的第 3 位置 1、清 0、读出

**验收**：

- 不看资料，从空文件写出 1、2、4 三个程序并编译通过
- 能解释 `volatile` 在 `while (!flag);` 这种轮询里的作用
- 能说出「数组名和指针的差别在哪」

**下一步**：S2。

### S2 电路与数字逻辑

**目标**：看懂开发板原理图上的大部分符号，能算、能量。

**学什么**：欧姆定律、分压、KVL/KCL、戴维南、RC 时间常数；二极管限流、三极管开关（够用即可）；布尔代数、组合逻辑、触发器、状态机。

**主推荐**：[02 板块的电路原理](/courses/circuit-xjtu)（[课程页](/courses/circuit-xjtu)已写清先修与完成标准）+ [07 板块的数字逻辑部分](/07-digital-fpga/README)。

**练习**：

1. 手算一个分压电路并实测，记录误差与原因
2. RC 充电：算 `τ`，用 LTspice 仿真，再用万用表每隔 2 秒记一次电压，画三条曲线对比
3. 用一个按键 + 上拉电阻 + 软件消抖，画出时序（按下、抖动、稳定）
4. 把「三人表决器」的真值表化简并搭出来（逻辑门或 MCU 模拟均可）

**验收**：

- 能解释 63.2% 从哪来
- 实测与仿真差 20% 时，能列出三种可能原因并逐个排除
- 能画出「按键抖动」的时序并说明消抖为什么要 10 ms 量级

**下一步**：S3。

### S3 MCU 外设

**目标**：让一颗 MCU 按你的意图工作，而不是照着例程改。

**学什么**（按顺序，一个外设一个实验）：GPIO 输出 → GPIO 输入 → 外部中断 → 定时器（定时中断 / PWM 输出 / 输入捕获）→ UART 收发。

**主推荐**：[浙江大学 STM32嵌入式系统](/courses/stm32-zju)（走寄存器 + 库函数，适合理解底层）**或** [03 板块的电科大 CubeMX + HAL 课](/03-embedded-mcu/README)（走图形化配置，上手快）。**选一门，另一门当对照**，不要同时跟两门。

硬件参考手册：[ST 官方 MCU 页面](https://www.st.com/en/microcontrollers-microprocessors/stm32-32-bit-arm-cortex-mcus.html)（按你的具体型号找 RM/DS）。

**练习**：

1. **从空工程开始**，不用任何现成例程工程。配置时钟树，让一个定时器每 1 ms 中断一次，翻转一个 LED
2. 用 UART 每秒上报一次按键计数，中断里只置标志位，主循环负责发送
3. PWM 输出驱动 LED 呼吸，用示波器或逻辑分析仪量占空比
4. 输入捕获测一个外部方波的频率

**验收**：

- 能用示波器/逻辑分析仪量出 1 ms 中断周期与串口波特率
- 能解释 HAL 回调在哪个上下文被调用、为什么中断里不该做阻塞操作
- 故意把中断优先级配错，能定位现象
- **不算过关**：拿别人的工程改几个宏定义跑通，却说不清时钟从哪来、中断向量表在哪

**下一步**：S4。

### S4 总线与传感器

**目标**：和外部芯片对话。

**学什么**：I2C（起始/地址/应答/数据）、SPI（四线、时钟极性/相位）、ADC（分辨率、参考电压、采样时间、量程换算）。

**练习**：

1. 用 I2C 扫描总线，打印所有应答地址
2. 读一个 I2C 传感器（AHT20 / SHT30 / BH1750 任一），把原始字节按 datasheet 换算成物理量
3. 驱动 SSD1306 OLED，显示传感器读数
4. 用 ADC + DMA 做多通道采样，串口输出

**验收**：

- 能查 datasheet 确认地址与寄存器，而不是抄教程
- 屏幕读数随环境真实变化（用手捂住传感器数值应下降或上升）
- 拔掉传感器，程序显示「传感器离线」而不是卡死
- 能说清 ADC 的读数 `4095` 对应多少伏、为什么

**下一步**：S5。

### S5 工程化

**目标**：代码能交给别人，而不是只有你能跑。

**学什么**：Git（提交、分支、回退）、目录分层（驱动 / 应用 / 配置）、断言与错误码、日志、看门狗；按需再上 FreeRTOS（任务、队列、信号量）。

**主推荐**：[08 板块的 Git 与工程组织段落](/08-hardware-toolchain/README)、[FreeRTOS 官方文档](https://www.freertos.org/)（03 板块有完整卡片）。RTOS 不急于一时——**等你有两个以上任务真的需要并行时再上**。

**练习**：

1. 给项目建 Git 仓库，按「驱动 / 应用」分目录，提交记录能看出每一步做了什么
2. 加一个错误码体系：函数返回 `int`，0 成功、负数错误码，调用处必须处理
3. 开看门狗，并故意制造一次死循环，确认系统能复位

**验收**：

- 把仓库给别人，对方不看文档能编译并通过
- 出错时串口打出「哪一步失败、错误码多少」，而不是一片空白
- 能解释看门狗复位和手动复位的区别

**下一步**：S6。

### S6 综合项目

两个项目，按条件选一个。两个都要写验收记录。

#### 项目 A：环境监测节点（有传感器时）

**硬件**：STM32 最小系统板或 Nucleo、I2C 传感器一块、SSD1306 OLED、按键、USB 转串口。

**功能**：采集温湿度/光照，OLED 显示，按键翻页，串口每秒输出一行 CSV。

**验收（四条，都能当众演示）**：

1. 上电 3 秒内屏幕出读数，数值随环境变化，不是写死的常量
2. 串口每秒输出 `时间,温度,湿度,光照`，格式固定，脚本能解析
3. 拔掉传感器后显示「传感器离线」，程序不卡死，插回能自动恢复
4. 连续上电 48 小时不重启、不花屏、串口不中断

#### 项目 B：串口命令行控制板（只有板子时）

**硬件**：一块 STM32 + USB 转串口。不需要任何传感器。

**功能**：通过串口接收文本命令，控制 LED 亮度（PWM）、读 ADC 电压、查询运行时间。

**验收**：

1. 支持 `led <0-100>`、`adc`、`uptime`、`help` 四条命令，非法参数返回错误提示且不崩溃
2. 命令解析不阻塞：输入一长串字符不会导致 PWM 停振
3. 连续运行 48 小时，命令响应正常
4. 代码分驱动层与应用层，新增一条命令不需要改驱动

## 实验方法：五步循环

每个阶段都按这个循环做，不要跳：

```text
理论分析 → 仿真预测 → 实验测量 → 解释差异 → 整理记录
```

以 S2 的 RC 充电为例：

| 步骤 | 具体动作 | 产出 |
|---|---|---|
| 理论分析 | 手算 τ = RC = 1 kΩ × 1 mF = 1 s，63.2% 处约 1 s | 一张纸上的预期曲线 |
| 仿真预测 | LTspice 搭同一个电路，跑 5 s 瞬态 | 波形截图 + 数据点 |
| 实验测量 | 面包板搭，万用表每 2 s 记一次电压 | 一张实测表 |
| 解释差异 | 实测比仿真慢 15%：电容实际容量偏大或万用表内阻分流 | 一段原因分析 |
| 整理记录 | 三组数据放一张表，附结论 | 可复现的实验记录 |

**没有仪器时的替代**：用 MCU 的定时器捕获 PWM 高电平时间，反推占空比。这能验证频率与占空比，但看不到毛刺、量不到上升时间——**在记录里写明限制**。

## 常见的五种失败

1. **跳过 S0 直接上 MCU**。结果每次不亮都只能靠猜，一周后放弃。
2. **同时跟两门 MCU 课**。一门讲寄存器、一门讲 HAL，两套工程结构混在一起，最后哪个都不熟。
3. **拿现成工程改宏定义**。能跑，但一换芯片就全崩，因为不知道自己在改什么。
4. **只做实验不写记录**。两周后回看，不记得当时的差异原因，等于没做。
5. **过早引入 RTOS**。三个任务用 `while(1)` 轮询完全够用，上 RTOS 反而让调试变复杂。

- 不包含模电的放大器设计、PCB 设计、EMC。这些做板子时再补，归 [02](/02-circuit-electronics/README) 与 [08](/08-hardware-toolchain/README) 板块。
